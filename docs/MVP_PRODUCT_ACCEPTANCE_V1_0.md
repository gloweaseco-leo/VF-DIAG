# VF-DIAG MVP｜SiteOne-first 产品与验收任务书 V1.1

**Owner批准方向：2026-11-22；2026-11-23完成客户价值补强。状态：MVP实施依据，尚未实测、尚未上线。执行：Cursor；Owner负责业务/技术验收。**

## 1. 唯一商业目标

让制造业及B2B外贸企业负责人在**输入网址、一次声明授权**后看到真实的海外买家视角体检：知道网站已有优势、最多三项值得关注的问题、证据和合理下一步，并能自愿联系 VEYFRONT 讨论局部优化或 Rebuild。

不是完整八维56项诊断平台、VRAE复制品、SEO打分器或必须诱导重建的销售漏斗。八维56项保留为长期专业能力模型，**不是MVP的验收清单**。有效咨询以用户主动表达需求为准；提交网址不是销售线索。

## 2. 唯一初始引擎及版本裁决

- MVP **只使用 SiteOne Crawler 一个初始检测引擎**。**M0固定正式发布版 v2.5.1（MIT）**作为可复验基线，记录二进制校验值及CLI参数；**M1不预先永久锁死版本**：仅当真实买家信息需求确有缺口时，可提交经过隔离验证的具体版本/提交与差异回执，Owner批准后变更固定版本。未经通过不得直接追踪main运行。暂不引入其他检测框架。
- v2.5.1 发布文档已确认：原生 HTML 审计报告、结构化 JSON、网页技术/SEO/安全/链接检查、可选 Chromium 渲染及截图、可选 AI 技术摘要（summary）。**专业原生报告直接复用，不重新开发其图表与技术详情。**
- **正式版能力与边界**：v2.5.1 标签文档明确包含 `--markdown-export-dir`、`--ai-actions=custom`、`--ai-prompt-file`；它们可作为**少量代表性产品页面的条件性内容观察手段**，必须先跑通实际产物、限制模型调用、核对摘录来源，不是自动核验产品参数。`--ai-report=extract`、`--ai-report=ia`、`--ai-geo`、`--events-file`、`--control-stdin` 出现在较新main文档，**v2.5.1标签文档未列出**，不得作为MVP默认依赖。
- v2.5.1 的 AI summary 主要围绕技术汇总，不是工业采购任务结论；**不得将其或0–10技术质量分直接当作经营判断或重建必要性。**
- SiteOne 具备的SMTP、上传、镜像克隆、缓存预热、压测等功能**不进入MVP运行配置**。

## 3. MVP只做四步客户闭环

1. **输入**：一个 HTTPS 网址 + 一次明确的站点拥有者/授权运营者声明勾选；不要求注册、手机号、邮件或预留企业微信。
2. **检测**：受控 Worker 有界启动 SiteOne；显示真实“验证中/扫描中/报告整理中/已完成”等状态；可以停止；产生真正 HTML、JSON 和执行回执。
3. **报告**：中文优先、移动端优先的单页客户摘要：已证实优势、三个买家问题（能否发现/看懂/联系）、**至少对一个抽样产品页面做真实可回查的信息观察、对一个联系入口做存在与可访问性观察**（如采样内不存在则明确NOT_CHECKED）、最多三项有证据的优先改善事项、合理下一步。专业细节打开原生报告。
4. **转化**：复用已核实的 VEYFRONT 承接入口：`https://veyfront.com/start/rebuild`（改造咨询）、`https://veyfront.com/contact#wechat`（企业微信）、`https://veyfront.com/contact#project-form`（自愿填写需求）。用户主动操作才进入联系流程，不自动写入营销线索。

## 4. 功能必须与证据匹配

| 客户问题 | MVP可依据的事实 | 不能声称 |
| --- | --- | --- |
| 海外买家能找到我吗？ | 抽样范围内的 URL、标题/H1、robots/noindex、sitemap、链接、HTTP状态及索引指令 | Google实际排名、已被某AI搜索推荐、保证获得曝光 |
| 海外买家能看懂产品吗？ | 发现的目录/产品相关页面、标题、摘要、可见公开信息及可访问资料链接（仅限确实获取到的字段） | 全部型号/关键参数已验证、企业不具备未找到的产品能力 |
| 海外买家能联系我吗？ | 联系/RFQ相关URL在采样中可发现及可访问、明显破链 | 表单已成功提交、邮件实际送达、销售已承接 |

对没有充分证据的项目用 NEEDS_CONFIRMATION / NOT_CHECKED；站点反爬、检测失败、采样不全不能自动算网站缺陷。首次报告**可明确建议“保留现站、暂无需重建”**。

### 4.1 从SiteOne事实到客户判断：M1最小映射规则

| 来源及事实条件 | 可写给客户的话（层级） | 禁止直接推断 |
| --- | --- | --- |
| `tables["404"].rows` 的 `url`、`sourceUqId`、`statusCode` 能定位到**被检查的实际产品/联系链接及其来源页面**，确认404 | “本次从某页面发现的某产品/联系链接返回404”（OBSERVED）；“通过该链接的买家可能无法继续访问”（INFERRED）；建议修复链接并复查 | 不能泛化为所有产品不能访问、真实询盘流失或必须重建 |
| `tables.seo.rows` 的 `urlPathAndQuery`、`title`、`h1`、`indexing`/ `robotsIndex` 有确切页面和返回记录 | “某个已检查页面缺少H1 / 显示noindex指令”（OBSERVED）；是否有业务影响需结合它是否为主要产品页且排除合理意图 | 不得声称整个站未收录、海外客户找不到；单独缺H1不自动列为重大问题 |
| `results` 和对应SEO/URL记录证实某重要产品页200、标题/介绍可见 | “本次发现并成功访问该产品页/产品信息入口”（OBSERVED，正向优势候选）；必要时引用**真实**Markdown摘录 | 不得宣称产品参数完整、选型成功、搜索平台已索引 |
| 发现联系/RFQ相关页面或链接，且被实际请求并取得可接受HTTP响应 | “本次找到并访问了公开联系入口”（OBSERVED，正向优势候选）；若明确404，可作为链接障碍 | **HTTP 200不能证明表单可提交、邮件可送达或销售会回复** |
| 扫描页面上未发现产品/联系入口、遇到JS加载失败、robots/WAF限制、达到页数上限或工具失败 | “在已检查范围内未发现/本次未完成验证”（NOT_CHECKED或NEEDS_CONFIRMATION） | 禁止判定企业没有产品、没有联系渠道或网站存在确定缺陷 |

以上字段以 **SiteOne v2.5.1 原生JSON实际数据**为准。输出中某个字段缺失或形式不同，不得通过猜测补齐；原始URL和来源页关系必须可重放。AI摘要、技术质量分和自然语言分类都不能替代原始引用。

### 4.2 M1 最小买家观察与改善决策

- **一个代表性产品观察**：从扫描确实发现的产品相关URL中选择一个，展示其URL、能确认的名称/标题、公开介绍摘录或文档入口、来源和**未确认信息**；如只能证明链接而无法读取正文，明确“只核实可访问，未核实规格”。
- **一个联系入口观察**：展示扫描内找到的联系/RFQ URL、对应状态与来源；不执行实际询盘，不验证送达。
- **优先事项排序**：先考虑已确认的买家路径阻断（如关键产品/联系链接404），再考虑影响重要页面理解的观察；同等条件优先证据完整、可复验、低成本修复的事项。单独H1/缓存/技术分扣分不能自动排在前列。
- **服务分叉**：单点可修复问题→局部优化；多项相互关联且已证实的信息架构/买家路径问题→可讨论专项升级；**Rebuild只能作为有充分结构性证据后的咨询选择，不得由评分、问题数量或模型建议自动决定**。没有明确问题→保留现站/暂不建议重建；采样不足→先核实再决策。
- **最低报告价值**：结果至少能讲清一个真实产品或联系入口的观察，并提供可回查证据；若无法观察到，必须呈现**部分诊断/样本不足**，不得包装为完整买家体检。

## 5. 数据与报告最小契约

- 单个 scan_job：不可预测的任务引用、目标域名、授权确认时间、状态、实际启动结束时间、SiteOne版本、运行预算与采集范围、失败原因、产物索引和过期时间。
- 原始工件：SiteOne HTML/JSON，执行退出码、stdout/stderr的脱敏诊断；可选截图仅在有安全隔离与预算时运行；原始报告不可被业务模型改写。
- 客户事实：原始 URL + 采集时间 + JSON表/字段或原文片段 + 采集范围 + OBSERVED / INFERRED / NEEDS_CONFIRMATION / NOT_CHECKED。
- 每条改善建议必须绑定可核查的事实、可能影响的买家步骤、改善动作；模型生成的推断不能被包装为事实。
- 没有证据就不输出负面结论；没有符合条件的事项就显示0项，而不是凑满3项。
- 所有未知项清楚展示；不以 SiteOne qualityScores 直接生成“应重建”结论。

## 6. 工程最小组成

- VF-DIAG 薄任务接口及客户报告页；独立的受控 Worker 运行 SiteOne；小型任务/工件存储。不做多租户业务中台、统一多引擎插件平台、CRM或复杂权限系统。
- 长时间爬取不放在 Vercel 普通网页请求中；VEYFRONT 正式域名、VRAE与L2M均不改动。
- **进度与停止兼容 v2.5.1**：以外部进程与任务记录提供真实阶段状态；无可靠分母时不显示完成百分比。停止/超时通过进程组（Windows需覆盖子进程树）及任务守护实现，不依赖尚未确认在该tag可用的事件或stdin协议。停止后区分已完成、部分、失败与用户取消。
- 预算建议起点（非实测性能承诺）：首次默认最多50个访问URL、深度≤3、站点请求速率≤1次/秒、Worker运行≤180秒、单站单任务；具体范围须在G0合成场景核对CLI参数的含义后固定。网页资产是否计入URL上限需明确。
- 对 JS-heavy 页面仅在安全隔离与网络出口限制通过后按需开启 Chromium 模式，不把截图作为M1阻断项。

## 7. 公开站点扫描安全关口

- 扫描前必须有用户声明授权；仅检查允许的 HTTPS 公网目标，限制跳转范围，验证DNS解析结果、重绑定、私网/链路本地地址、实际网络出口、浏览器子资源与代理配置；不得只依赖SiteOne内置域名过滤。
- 遵守 robots 与站点访问规则；限速/超时/页数/并发/响应体大小；执行容器或受限进程无云密钥及内网权限；对异常跳转或未知下载内容安全拒绝。
- 不登录、绕过验证码、提交询盘、发邮件、运行压力测试、镜像复制网站或写入客户系统。
- 报告链接不可猜测，不以网址查询参数泄露访问凭据；对外分享与导出须访问授权；原始HTML只能在隔离来源/沙盒或严格限制脚本的条件下浏览；明确数据留存期限并按期清理。
- 不把真实客户信息、源码凭据、原始授权材料或敏感工件提交公开 GitHub 仓库。

## 8. 三个开发批次与验收

**M0｜稳定原生报告**：用受控合成网站运行 SiteOne v2.5.1；真实输出HTML+JSON+退出码+运行配置；验证私网/非法URL拒绝、重定向、预算、超时及强制回收。产物可打开。**未通过安全关口不得扫描真实客户网站。**

**M1｜可向客户展示的闭环（首要目标）**：输入网址+一次授权→真实扫描→**代表性产品信息观察 + 联系入口观察**→中文客户报告（正面事实、最多三项问题、合理改造分叉）→原生专业明细→主动咨询。至少1个确实授权的制造业站点成功完成且包含足够的可回查产品与联系信息；无伪造进度/报告、无重大无据负面断言；手机端可读。若样本无法支撑产品/联系观察，标记部分诊断、不声称完整通过。无法获取授权站点时，只标注合成完成，不假报客户实测PASS。

**M2｜只根据客户反馈补强**：多页产品参数提取、复杂规格核验、可视化截图与更深入的采购路径研究（可选）。**M1已有的一页产品/一条联系入口的轻量观察不属于M2**。如确需新版SiteOne原生接口，先比较版本收益、兼容回归与预算，获得Owner批准；不为功能完整强制升级。M2不阻断M1。

每批返回：Git分支/PR/SHA、固定工具版本与依赖/许可证、可重放命令、产物链接（去敏）、成功及失败任务、耗时和资源、已证实事实及误判、截图或手机展示、阻断项。发布 VEYFRONT 正式域名必须由 Owner 单独批准。

## 9. GO / FIX / NO-GO

- **GO（仅独立预览/客户受控试用）**：M0安全PASS；M1真实报告链路PASS；已授权站点上至少有一项可回查产品观察及一项联系入口观察或明确呈现其未完成范围；重大未经证实负面断言为0；用户可打开证据与专业明细，知道为何保留、修复或考虑进一步咨询；咨询自愿。正式完整买家报告GO还需产品/联系观察均有可核实事实，不能以两项NOT_CHECKED冒充。
- **FIX**：真实扫描或报告可用，但内容/截图/移动端/状态存在可以修复的问题。
- **NO-GO**：任何公网越界、内网访问、不可终止任务、客户信息泄露、假检测数据、严重无据负面结论；禁止对外发布。

**执行原则：先得到一份真实可信的客户报告，再改善产品。**
