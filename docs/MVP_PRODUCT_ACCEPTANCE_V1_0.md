# VF-DIAG MVP｜SiteOne-first 产品与验收任务书 V1.0

**Owner批准方向：2026-11-22。状态：MVP实施依据，尚未实测、尚未上线。执行：Cursor；Owner负责业务/技术验收。**

## 1. 唯一商业目标

让制造业及B2B外贸企业负责人在**输入网址、一次声明授权**后看到真实的海外买家视角体检：知道网站已有优势、最多三项值得关注的问题、证据和合理下一步，并能自愿联系 VEYFRONT 讨论局部优化或 Rebuild。

不是完整八维56项诊断平台、VRAE复制品、SEO打分器或必须诱导重建的销售漏斗。八维56项保留为长期专业能力模型，**不是MVP的验收清单**。有效咨询以用户主动表达需求为准；提交网址不是销售线索。

## 2. 唯一初始引擎及版本裁决

- MVP 首次实现**仅使用 SiteOne Crawler**。首轮以正式发布版 **v2.5.1**（MIT）作为可复验基线，固定版本/二进制校验值/关键CLI参数。验证通过前不添加 Crawl4AI、Playwright、sitespeed.io、Stagehand、Docling、MinerU 或其他引擎。
- v2.5.1 发布文档已确认：原生 HTML 审计报告、结构化 JSON、网页技术/SEO/安全/链接检查、可选 Chromium 渲染及截图、可选 AI 技术摘要（summary）。**专业原生报告直接复用，不重新开发其图表与技术详情。**
- **版本陷阱**：截至本次核查，--ai-report=extract、--ai-report=ia、--ai-geo、--events-file、--control-stdin 出现在仓库 main 的较新文档，**v2.5.1 标签文档未列出**。不能直接当成 v2.5.1 的可用功能；如未来需要，另行固定已验证版本/提交并在隔离环境验证，不能阻断MVP。
- v2.5.1 的 AI summary 主要围绕技术汇总，不是工业采购任务结论；**不得将其或0–10技术质量分直接当作经营判断或重建必要性。**
- SiteOne 具备的SMTP、上传、镜像克隆、缓存预热、压测等功能**不进入MVP运行配置**。

## 3. MVP只做四步客户闭环

1. **输入**：一个 HTTPS 网址 + 一次明确的站点拥有者/授权运营者声明勾选；不要求注册、手机号、邮件或预留企业微信。
2. **检测**：受控 Worker 有界启动 SiteOne；显示真实“验证中/扫描中/报告整理中/已完成”等状态；可以停止；产生真正 HTML、JSON 和执行回执。
3. **报告**：中文优先、移动端优先的单页客户摘要：已证实优势、三个买家问题（能否发现/看懂/联系）、最多三项有证据的优先改善事项、未检查/待确认、合理下一步。专业细节打开原生报告。
4. **转化**：提供“查看专业明细”“自行改善”“咨询 VEYFRONT / 了解 Rebuild”链接，复用 VEYFRONT 现有 Rebuild 与企业微信入口；用户主动操作才进入联系流程，不自动写入营销线索。

## 4. 功能必须与证据匹配

| 客户问题 | MVP可依据的事实 | 不能声称 |
| --- | --- | --- |
| 海外买家能找到我吗？ | 抽样范围内的 URL、标题/H1、robots/noindex、sitemap、链接、HTTP状态及索引指令 | Google实际排名、已被某AI搜索推荐、保证获得曝光 |
| 海外买家能看懂产品吗？ | 发现的目录/产品相关页面、标题、摘要、可见公开信息及可访问资料链接（仅限确实获取到的字段） | 全部型号/关键参数已验证、企业不具备未找到的产品能力 |
| 海外买家能联系我吗？ | 联系/RFQ相关URL在采样中可发现及可访问、明显破链 | 表单已成功提交、邮件实际送达、销售已承接 |

对没有充分证据的项目用 NEEDS_CONFIRMATION / NOT_CHECKED；站点反爬、检测失败、采样不全不能自动算网站缺陷。首次报告**可明确建议“保留现站、暂无需重建”**。

## 5. 数据与报告最小契约

- 单个 scan_job：不可预测的任务引用、目标域名、授权确认时间、状态、实际启动结束时间、SiteOne版本、运行预算与采集范围、失败原因、产物索引和过期时间。
- 原始工件：SiteOne HTML/JSON，执行退出码、stdout/stderr的脱敏诊断；可选截图仅在有安全隔离与预算时运行；原始报告不可被业务模型改写。
- 客户事实：原始 URL + 采集时间 + JSON表/字段或原文片段 + 采集范围 + OBSERVED / INFERRED / NEEDS_CONFIRMATION / NOT_CHECKED。
- 每条改善建议必须绑定可核查的事实、可能影响的买家步骤、改善动作；模型生成的推断不能被包装为事实。
- 没有证据就不输出负面结论；没有符合条件的事项就显示0项，而不是凑满3项。
- 所有未知项清楚展示；不以 SiteOne qualityScores 直接生成“应重建”结论。

## 6. 工程最小组成

- VF-DIAG 薄任务接口及客户报告页；独立的受控 Worker 运行 SiteOne；小型任务/工件存储。不做多租户业务中台、统一多引擎插件平台、CRM或复杂权限系统。
- 长时间爬取不放在 Vercel 普通网页请求中；VEYFRONT 正式域名、VRAE与L2M均不改动。
- **进度与停止兼容 v2.5.1**：以外部进程与任务记录提供真实阶段状态；无可靠分母时不显示完成百分比。停止/超时通过进程组（Windows需覆盖子进程树）及任务守护实现，不依赖尚未确认在该tag可用的事件或stdin协议。停止后区分已完成、部分、失败与用户取消。
- 预算建议起点（非实测性能承诺）：首次默认最多50个访问URL、深度≤3、站点请求速率≤1次/秒、Worker运行≤180秒、单站单任务；具体范围须在G0合成场景核对CLI参数的含义后固定。网页资产是否计入URL上限需明确。
- 对 JS-heavy 页面仅在安全隔离与网络出口限制通过后按需开启 Chromium 模式，不把截图作为M1阻断项。

## 7. 公开站点扫描安全关口

- 扫描前必须有用户声明授权；仅检查允许的 HTTPS 公网目标，限制跳转范围，验证DNS解析结果、重绑定、私网/链路本地地址、实际网络出口、浏览器子资源与代理配置；不得只依赖SiteOne内置域名过滤。
- 遵守 robots 与站点访问规则；限速/超时/页数/并发/响应体大小；执行容器或受限进程无云密钥及内网权限；对异常跳转或未知下载内容安全拒绝。
- 不登录、绕过验证码、提交询盘、发邮件、运行压力测试、镜像复制网站或写入客户系统。
- 报告链接不可猜测，不以网址查询参数泄露访问凭据；对外分享与导出须访问授权；原始HTML只能在隔离来源/沙盒或严格限制脚本的条件下浏览；明确数据留存期限并按期清理。
- 不把真实客户信息、源码凭据、原始授权材料或敏感工件提交公开 GitHub 仓库。

## 8. 三个开发批次与验收

**M0｜稳定原生报告**：用受控合成网站运行 SiteOne v2.5.1；真实输出HTML+JSON+退出码+运行配置；验证私网/非法URL拒绝、重定向、预算、超时及强制回收。产物可打开。**未通过安全关口不得扫描真实客户网站。**

**M1｜可向客户展示的闭环（首要目标）**：输入网址+一次授权→真实扫描→中文客户报告→原生专业明细→主动咨询。至少1个确实授权的制造业站点成功完成；无伪造进度/报告、无未经证实的重大负面断言；手机端可读。无法获取授权站点时，只标注合成完成，不假报客户实测PASS。

**M2｜只根据客户反馈补强**：选定重要产品页的事实提取、截图与轻量AI辅助文案（可选）。如果 v2.5.1 不支持相应原生接口，先比对采用经过验证的新版本的收益与回归风险；不为功能完整强制升级。M2不阻断M1。

每批返回：Git分支/PR/SHA、固定工具版本与依赖/许可证、可重放命令、产物链接（去敏）、成功及失败任务、耗时和资源、已证实事实及误判、截图或手机展示、阻断项。发布 VEYFRONT 正式域名必须由 Owner 单独批准。

## 9. GO / FIX / NO-GO

- **GO（仅独立预览/客户受控试用）**：M0安全PASS；M1真实报告链路PASS；重大未经证实负面断言为0；用户可打开证据与专业明细，知道是否需改造；咨询自愿。
- **FIX**：真实扫描或报告可用，但内容/截图/移动端/状态存在可以修复的问题。
- **NO-GO**：任何公网越界、内网访问、不可终止任务、客户信息泄露、假检测数据、严重无据负面结论；禁止对外发布。

**执行原则：先得到一份真实可信的客户报告，再改善产品。**
