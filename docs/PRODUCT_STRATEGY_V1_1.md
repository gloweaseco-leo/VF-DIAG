# VF-DIAG｜产品、增长与任务架构 V1.1

日期：2026-11-22；状态：Owner 决策底稿，开发中，**未上线**。面向：制造业及B2B跨境出口企业；中文优先、英文内容要能服务真实海外买家。

## 0. 北极星与商业边界

不是“SEO打分器”，不是“VRAE简化复刻”，也不是“给老板制造恐慌以促进重建”。

北极星：**已授权完成有效体检的客户，能够准确理解一个优先改进事项及其证据，并能自主决定是保留、局部优化还是寻求服务**。客户主动留下咨询需求才计为商业线索；网址提交≠销售线索。对商业收入、转化提升不得无证据承诺。

目标用户：制造业老板/总经理（预算与方向）、外贸负责人（询盘与供应商展示）；市场运营和技术人员为专业明细阅读者。

## 1. 制造业老板的三重焦虑（用户心智）

- **AI时代被看见：** 海外买家通过传统搜索或AI寻找供应商时，有没有机会被检索和准确描述？
- **采购前判断：** 海外买家能否看懂产品规格、应用工况、认证声明并判断是否匹配？
- **把关注变成商机：** 感兴趣的买家能否直接联系？网站投入到底该优化哪里？

报告应围绕买家任务及真实证据，既呈现可用之处也呈现障碍；不为了出售Rebuild而夸大问题。

## 3. GEO 证据等级

**GEO-0 可访问**（robots/noindex/公开可访问技术策略）；
**GEO-1 可理解**（产品/企业实体清楚、有效文本、来源和规格、结构化数据与页面一致）；
**GEO-2 平台观察**（客户授权读取GSC/Bing官方报表，明确是曝光/引用而非点击或成交）；
**GEO-3 问题实验**（按真实采购场景在明确的平台、国家、语言、日期、同一询问集抽样，保存答案和引用; 不冒充全市场统计）。

首期 GEO-0/1 必做；GEO-2/3 是 P1，具备真实授权、合法API或官方导出后开始。永不出售“必然获得AI推荐”。

## 4. 真正触动客户的四个展示瞬间（非工程KPI）

1. **海外买家第一视角：** 对所选产品呈现“能否从导航找到、关键规格能否读懂、联系入口是否可用”，附网页链接/截图/测试范围。
2. **AI能否读懂：** 在已抓取产品文本范围内展示可核实的产品名称、参数、应用场景；缺失部分明确为未观察到/需确认，而非假装AI能预测排名。
3. **当前强项 + 最值得改善的三个环节：** 每个环节标注影响的采购步骤、可观察证据、建议动作、人工确认条件。没有证据的项目不列为已确认障碍。
4. **决策分叉：** “无需重建/局部优化/专项升级/可讨论Rebuild”，并解释为什么。所有结果均提供不强制登记的基本结论；咨询是自愿的。

不要以炫耀性大分数、制造不存在的订单损失或伪造竞对覆盖率来触发焦虑。

## 5. 四大架构

**业务：** 免费有效体检 → 可解释的证据与行动 → 自行改进/联系VEYFRONT →（有需要时）专项修复/重建/持续经营。观测“结果查看率、三项建议阅读率、主动咨询率、经核实的意向线索率”，不能把提交任务量当成有效线索量。

**应用：** VEYFRONT负责品牌/客户UI/线索；VF-DIAG独立拥有任务/开源适配/事实与报告API；VRAE独立高级诊断研发，本阶段不上线、不集成；L2M独立建设交付。不得共享数据库，不预设VRAE接口。

**数据：** scan_job、website_snapshot、page_observation、raw_tool_artifact、finding、recommendation、presentation。每项 finding 包含来源URL、时间、工具+版本、抓取范围、证据引用、结论级别 OBSERVED/INFERRED/NEEDS_CONFIRMATION/NOT_CHECKED。推荐必须可以回溯到已有事实；任何AI生成判断不可以虚构数据。

**技术：** 有界、可终止的受控Worker（SiteOne优先验证）；Crawl4AI只在复杂产品内容解析确实需要时增加；Unlighthouse/Lighthouse做可选专项；规范化数据适配器；独立可替换的客户展示层。原生工具HTML可做技术附录，但不是产品第一屏。所有外部目标必须得到授权并执行 SSRF/DNS/redirect/网络/robots/速率/任务限额等保护；SiteOne内置克隆、压测、SMTP等高风险/非必要能力默认禁用。任何真实数据、密钥、客户网站授权材料不可提交公开仓库。

## 6. 开源组合与验证准则

- [SiteOne Crawler](https://github.com/janreges/siteone-crawler) · MIT · JSON + HTML，**P0候选主引擎，不代表已选型通过**；
- [LibreCrawl](https://github.com/PhialsBasement/LibreCrawl) · MIT · 完整Web多租户系统，必须用相同的真实授权样本对比它的应用维护与客户适配成本；
- [Crawl4AI](https://github.com/unclecode/crawl4ai) · Apache-2.0 · AI友好Markdown/结构化提取，条件引入；
- [Unlighthouse](https://github.com/harlan-zw/unlighthouse) · MIT / [Lighthouse](https://github.com/GoogleChrome/lighthouse) · Apache-2.0 · 专项性能；
- GEO小众开源可借鉴思路，但不直接作为主生产依赖；稳定性、许可证、输出可复核和后续维护优先于Star数。

采用工具前提交版本、许可证、SBOM/主要依赖、稳定性、吞吐/资源、可观测性、安全和业务准确性对比。许可证归属及NOTICE按实际发布形式保留。

## 7. Cursor开发批次与客户验收

**D0｜真实样本+框架基线**：同一组有授权的工业站样本，核对SiteOne与LibreCrawl的页面覆盖、产品详情识别、输出和报告；先可实用再谈炫技。交付对比表及实际原生报告。未满足数据质量阈值不得直接宣布选型终局。

**D1｜最小完整任务**：一次网址与授权 → 有界扫描 → 真实原生HTML报告+JSON → 可追踪结果 → 安全可复测。无需登录、无需先留电话。不对公共互联网放行。

**D2｜买家视角业务层**：首批P0四模块，每个建议必须附证据与范围；至少可以正确说“未确认/不建议重建”。提供可解释数据格式。

**D3｜客户体验层**：中文优先响应式页面；摘要、三个优先事项、证据、已确认/待确认、专业明细、可选咨询。独立预览，未获Owner验收不得修改veyfront.com正式页面。

**D4｜商业试验/独立验收**：至少5个跨产品类型、授权工业网站 + 已知好坏正反样例。核查抓取、证据可靠性、未经证实的负面陈述为0、无越界动作；由行业人员盲审是否真能指导下一步。对免费访问/咨询行为分开统计。Owner独立决定是否与VEYFRONT集成和上线。

**明确冻结：** VRAE不上线；不基于VRAE数据契约拼接；不新建大而全增长CRM；不承诺排名/销量；不自动部署或向任何站提交真实商业交互。

## 8. 工程汇报格式

每批提供：分支/PR/SHA、开源版本与许可证、真实/合成样本清单（脱敏）、通过与失败项、扫描覆盖/耗时/资源、证据引用、正反样本报告、已知限制、CI回执、下一批建议。未经事实核实不得写 DONE。
