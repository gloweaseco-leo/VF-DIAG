# VF-DIAG MVP｜客户报告与交互设计要求 V1.1

**2026-11-22建立，2026-11-23完成M1客户价值补强 · 中文优先、手机优先 · SiteOne-first MVP · 与 [产品与验收任务书](MVP_PRODUCT_ACCEPTANCE_V1_0.md) 配套。**

## 1. 设计目标

制造业老板看到报告的前20秒内应知道三件事：**网站有哪些已确认优势、哪个具体产品/联系路径被实际观察、哪一项改善最值得做（或为何暂不需要改造）**。外贸负责人可以展开买家路径，技术负责人能打开原始技术证据。

只需要**一个输入/授权页 + 一个扫描状态页 + 一个客户报告页**（状态页可以与报告页共用路由）。原生 SiteOne HTML 作为可打开的专业附件，不再重建 SiteOne 的专业仪表盘。

## 2. 客户流程（不强制留资）

1. 输入 HTTPS 网址；展示单次授权声明：“我确认对该网站拥有管理权限，或已获得网站管理者授权进行公开页面诊断。”需主动勾选才能开始。
2. 真实任务状态：验证目标 → 等待任务 → 检测网站 → 整理报告 → 可查看结果。任务未结束不出现假报告或虚构百分比。用户可取消，失败后提供原因和安全重试入口。
3. 完成后进入独立中文结果页；首屏显示网站、检测时间、范围、证据质量及关键结论。
4. 客户可查看原生明细、复制/分享有权限的结果链接、自行改善，或主动进入 VEYFRONT 现有企业微信与 Rebuild 服务；**不自动提交客户信息、不强制注册手机号/邮箱**。

## 3. 报告单页的信息架构（按出现顺序）

### A. 报告抬头
- VEYFRONT｜海外买家视角网站体检
- 网站域名、实际检测时间及时区、已检查页面数、样本范围。
- 检测状态：完成／部分完成／有范围限制。部分完成必须显著说明“本结论仅针对已检查页面”。
- 不展示“企业整体增长评分”“重建指数”；SiteOne原生技术质量分仅在专业报告内显示，不能作为商业销售结论。

### B. 先讲保留优势
- 有真实证据时，展示 1–3 条当前网站做得好的地方，含来源。
- 如果缺乏可确认优势，说明“本次样本不足以确认现有优势”，不得编造“网站已经非常优秀”。

### C. 三张买家任务卡
1. **海外买家能找到吗？**：访问/索引基础、栏目及主要产品链接的可发现性。不得宣称真实SEO排名或AI引用。
2. **海外买家能看懂吗？**：**M1必须尝试展示一个真实抽样的产品页面**（页面URL、可证实的标题/产品名称、公开介绍原文摘录或资料链接）。如果没有抓取到内容，只能写“发现页面/入口，规格未核查”，不能编造型号、参数或实际买家理解情况。
3. **海外买家能联系吗？**：**M1必须尝试展示一个真实联系/RFQ入口**（来源页、目标URL、确实观察到的访问状态）；HTTP 200 只能证明该请求可访问，**不等于表单可提交或询盘已送达**。

每卡按“本次确实看到什么 → 这可能怎样影响买家 → 原始证据 → 下一步”表达；结果为 OBSERVED / INFERRED / NEEDS_CONFIRMATION / NOT_CHECKED。无法观察到产品/联系入口时明确样本不足，不以空卡、红叉或泛泛的‘建议加强展示’冒充诊断。

### D. 最值得优先处理的事项
- 最多3条，**优先真实产品或联系路径的已证实阻碍**，其次为明显影响主要页面的信息表达问题；证据同等时优先能够具体修复的事项。**允许0、1、2条**，不为填满数字而创造问题。
- 事实陈述、影响买家哪一步、证据原文/URL/时间/范围、建议动作、需要谁确认，必须分开表达。
- 负面事实没有准确引用或属于扫描器故障时，不列为“已确认问题”。
- 技术层面的非最佳实践，不自动升级成“流失订单”“必须 Rebuild”。

### E. 改善方案分叉
- **保持现状 / 自助处理**：已检查范围内未见重大障碍，或只是轻微可自助修复问题。**采样不足时只建议继续核实，不得直接判为表现良好。**
- **局部优化**：具体页面或路径存在可独立解决的问题；
- **专项升级**：部分内容/技术表现需要集中处理；
- **可讨论 Rebuild**：多处相互关联的结构性采购障碍有可靠证据，**只是主动咨询选项，不能由SiteOne技术评分、H1缺失或单个404自动触发**，不自动报价。

每种建议都要有“为什么”，无证据时不给定重建结论。

### F. 原生技术明细与服务入口
- “查看完整技术检测报告”打开 SiteOne 原生 HTML 的独立受限阅读页面；必要时附 JSON 下载（不必把 JSON 放首屏）。
- 使用 VEYFRONT 仓库已核实的现成入口：**咨询改造** `https://veyfront.com/start/rebuild`；**企业微信** `https://veyfront.com/contact#wechat`；**填写项目需求** `https://veyfront.com/contact#project-form`。不另造二维码、CRM、聊天系统或邮件外发。前端显示对应真实服务，不可将联系按钮伪装成已诊断通过。
- 客户摘要保持独立，不把原生报告质量分直接复制到主屏。

## 4. 一张事项卡的统一内容格式

**标题：** 用制造业老板懂的自然语言描述所见事实，不把猜测写成断言。

**事实 / OBSERVED：** 例如“本次已检查的某个产品详情链接返回404”（只有扫描器确实记录该来源时才能展示）。

**可能影响 / INFERRED：** “通过此链接寻找产品的采购商可能无法访问该详情页”。不能写“损失30%询盘”。

**来源：** 原始页面URL + 被检查的目标URL + 检测时间 + SiteOne结果对应字段/记录；有截图时可查看原始区域。

**建议：** “核实链接与对应产品页，修复后复查”；仅当多处结构性障碍有证据时才讨论重建。

**待确认：** 只有站点管理者/业务人员能确认的实际运营或产品事实，明确列为待确认。

### 4.1 M1 需要交付的两张真正有内容的观察卡

| 卡片 | 必须显示 | 空缺或异常时显示 |
| --- | --- | --- |
| 代表性产品页面 | 真实URL、页面标题或经原文核验的产品名称、可见简介/资料链接（确实读取到才展示）、对应SiteOne证据 | “本次已发现产品入口，但未核实规格”或“当前采样未发现可确认的产品页”，标NOT_CHECKED，不生成缺陷 |
| 联系/RFQ入口 | 来源页面、目标URL、实际访问状态、对应SiteOne证据 | “仅发现联系入口，未验证表单提交”或“本次未找到可核实入口”，标NOT_CHECKED/NEEDS_CONFIRMATION |

产品卡和联系卡是三大买家问题中的**最小证据支点**，不新增一个复杂功能页；若二者都无法核实，报告必须称“初步技术扫描/买家信息尚待验证”，不可称完整买家体检。

### 4.2 报告内的商业转化与最小行为记录

- 主要行动随报告结论变化：已确认局部问题→“查看如何修复”；多项结构性问题→“讨论网站升级”；暂无明显问题→“查看专业明细/保留现站建议”。企业微信始终为**自愿入口**，不使用“您的网站必须重建”文案。
- MVP只需区分三种可测行为：`report_viewed`（有效报告阅读）、`rebuild_link_clicked`（主动查看升级咨询）、`wecom_link_clicked`（主动打开微信联系）。使用匿名任务引用聚合，不附带客户输入的网站内容、密钥或私有工件。
- 以上都是**阅读/点击意向**，不是“有效销售线索”“已经加上企业微信”或“成交”；实际咨询与有效商机只有 VEYFRONT 已有渠道核实后才可统计。若暂不能跨站关联，先保留匿名点击事件和可核实的报告访问计数，**不为打通埋点新增CRM**。
- 报告分享链接只用于受控查看；不通过咨询URL参数传输私人报告引用或采集证据。

## 5. 四种结论标签和中文文案

| 事实等级 | 面向用户的表达 | 不允许做的事 |
| --- | --- | --- |
| OBSERVED | “本次检测已确认” | 将技术数据外推成销量或企业能力 |
| INFERRED | “可能影响／基于现有证据推断” | 不标注推断来源而写成事实 |
| NEEDS_CONFIRMATION | “需要您或网站管理者确认” | 写成确定缺陷 |
| NOT_CHECKED | “本次未检测” | 写成正常或失败 |

表达应节制，避免“AI不推荐您”“网站正在丢失客户”“不重建就没有询盘”等无法验证的营销恐吓。

## 6. 手机端和视觉原则

- 沿用 VEYFRONT 现有品牌视觉语言与中文字级，不另外发明一套品牌UI。信息层级清晰、适度留白、内容密度合理。
- **手机优先**：单列内容，关键结论先于长图表；证据链接和引用容易展开/复制；长网址折行或可横向查看，不撑破页面。
- 顶部明确域名与检测状态；移动端底部仅保留“查看证据 / 联系咨询”两个实用入口，避免重复导航占屏。
- 客户首屏不展示庞大的雷达图、夸张百分比或没有含义的彩色分数；优先“已确认事实”“有价值的改善动作”。
- 色彩用于区分确实的重要状态，不把所有未检项涂红。满足文字对比、触控范围与键盘操作的基本可访问性。
- 网站截屏只在实际截图已成功、安全存储时出现；没有截图时应使用URL和原生结果，**不得自动生成示意图冒充客户站点证据**。

## 7. 全状态设计（必须真实）

| 状态 | 客户可见内容 |
| --- | --- |
| 输入错误 / 非允许目标 | 明确原因，禁止创建扫描 |
| 排队 | “等待开始检测”，不给虚假完成百分比 |
| 运行中 | 真实阶段和已知扫描统计；未知数量不显示 |
| 整理报告 | 明确正在从实际结果生成摘要 |
| 完成 | 可打开报告、专业明细、明确扫描范围 |
| 部分完成 | 已确认结果与未检范围分开；不得宣称完整评估 |
| 失败 | 无法确认网站结论，显示故障原因与重试方式 |
| 用户取消 | 已取消扫描，不自动声称网站问题 |
| 报告过期 | 清晰提示已过期，允许重新授权启动新检测 |

免费报告无需创建账号；分享访问要经过不可猜测的授权链接或等效机制，控制 Referer/索引和数据泄漏，不在公开站点泄露客户原始工件。

## 8. 实施与验收（不设计大型前端工程）

- **M1必做一页产品、一条联系入口的轻量事实观察**，以及真实状态、中文摘要、原生报告和可选择的咨询。M2再按客户反馈增加更多产品页深度提取、复杂规格核查与截图，不扩大M1工程。
- 使用真实 SiteOne JSON 生成客户卡片；无证据时宁可少展示。SiteOne 评分属于技术附件，不直接影响建议分叉。
- 必须提供三种报告样本供Owner审阅：**有明确的产品/联系路径问题、抽样良好无需重建、采集不全/失败**。均应展示对应产品/联系观察卡与实际来源。可先用标注为合成的安全Fixture测试UI，但正式验收需真实授权站点。
- 提交桌面和手机真实截图、长URL/空数据/部分完成/过期状态测试；不存在假进度、假问题、假营销线索。
- 主域名 veyfront.com 不自动修改、不自动部署；独立 VF-DIAG 预览通过 Owner 业务验收后另行决定官网对接。

**一句话验收：老板看完不需要懂技术，也知道“我已经做对了什么、应该优先改善什么、为什么值得或不值得重建”。**
